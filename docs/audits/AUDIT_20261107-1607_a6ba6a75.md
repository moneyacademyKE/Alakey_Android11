## Rich Hickey pass

- **FactEntity.kt (20)** a good small record whose identity contains a wall-clock millisecond, which turns "the same fact asserted twice" into a collision instead of a value (L11, M69 family).
- **FactDao.kt (48)** five queries where two would do — `getFactsUsingEntity`, `getAllFacts`, `getFactsUsingAttribute`, `getLatestFacts`, `compact` all express "latest per key" differently. The complection: history and current-value live in one table with no view separating them.
- **FactStore.kt (37)** thin and honest, except `getAttribute` (:28-33) hand-rolling in Kotlin what SQL already does, for zero callers (L72).
- **InformationModel.kt (50)** the best-shaped domain file in the repo — pure, no IO, one job. Its defect is that the vocabulary is string constants with no compiler enforcement on the write side (L73).
- **PlaybackStateRepository.kt (68)** right shape (small, injected, IO at the edges) but :33,:52,:60,:65 each hydrate the ENTIRE library to answer one ordering or one max — M72/M43's cost surfacing as API design.
- **UniversalRepository.kt (73)** pure delegation as M34 established; the three `combine` flows are the honest reactive shape, but they subscribe to history rather than state (M72).
- **The complection to name:** the `facts` table is asked to be BOTH an event log and a current-state cache, and every consumer pays for the log while wanting the cache. Three of this shift's four items (M72, M52-SHARPEN, L73) are that one missing distinction — and `getLatestFacts` already implements the cache, used by exactly one caller. Rejected alternative: a second `current_facts` table (adds a write path and a sync bug class); the cheapest correct move is latest-only reads over the existing table, plus a delete on unsubscribe.
