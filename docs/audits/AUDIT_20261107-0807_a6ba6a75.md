### M63 detail — why dead DI costs more than dead code

Dagger only instantiates a `@Provides` when something requests the type, so all three
(`provideAudioAttributes` :19-24, `provideExoPlayer` :26-34, `provideMediaSession` :36-41) are
never called. Two concrete costs beyond the 43 LOC:

1. **The recipes disagree.** `MediaModule.kt:22` sets `C.AUDIO_CONTENT_TYPE_MUSIC`; the live
   `AudioSystem.kt:30` sets `C.AUDIO_CONTENT_TYPE_SPEECH`. The live one also carries
   `setSeekBackIncrementMs`/`setSeekForwardIncrementMs` (:36-37, `SKIP_MS = 30_000`) and
   `setSkipSilenceEnabled` (:39); the module carries none of them. Anyone reading the `di/`
   package to learn how the player is configured learns the wrong thing — including which audio
   focus/content-type semantics the app has.
2. **It is a trap for the H2 version-bump work.** media3 is pinned at 1.2.0 and H2 asks for a bump.
   A media3 API change now has two call sites to update, one of which does not matter, and the
   dead one is the one that *looks* authoritative (`di/` is where DI is supposed to live).

`git diff --stat a6ba6a75 e1576f7 -- app/src/main/java/com/example/alakey/di` = **empty** → PR #76
does not touch it, so this is live at HEAD *and* survives the round-1 fix branch.
Fix (one line of intent, pick one): delete `MediaModule.kt`, or delete `AudioSystem`'s builder and
inject the module's `ExoPlayer`. Two construction recipes for one object is the defect; either
single owner fixes it.

### M64 detail — distinct from H5 / L48 / M60

Same user-visible outcome as **H5** (audio dead until the process dies) by a *different* trigger and
a *different* mechanism, so it needs its own fix:

- **H5** = `cleanup()` sets `cleanedUp = true` and never resets it (`:412-418`), triggered by
  `AppViewModel.onCleared()` → `playbackClient.cleanup()` (`AppViewModel.kt:384`).
- **L48** = the UI's own reconnect hook is `fun connect() = Unit`, i.e. the place a re-arm would
  naturally live is empty.
- **M60** = `cleanup()` is not a cancellation boundary (`scope` :66 never cancelled).
- **M64** = the retry *policy* itself terminates. Nothing was cleaned up, `cleanedUp` is still
  `false`, the guard at :139 would happily allow another attempt — there is simply no event left to
  ask for one. `reconnectJob` has completed, `controller` is `null`, and every user-facing call goes
  through `controller?.` null-safe no-ops.

Honest confidence: mechanism **h** (the control flow is 18 lines and fully read); user-visible
manifestation **m** — it needs the service to stay down past ~7.75 s, and per **M25** there is no
emulator job and no executed UI test, so nothing in this repo can demonstrate it.
Cheap fix shape: make exhaustion re-armable (a `connect()` on the next user intent — which is
exactly what L48's no-op hook is positioned to do), or drop the attempt cap and keep only the
backoff ceiling. Do **not** widen the backoff cap alone; that just lengthens the window before the
same permanent state.

## Rich Hickey pass

- **`di/MediaModule.kt` (43)** — *a map that lies.* DI's whole value is that the module declares who
  provides what; this one declares a provider nobody consumes, with a different configuration from
  the real one. Verdict: delete or adopt (M63).
- **`system/Lifecycle.kt` (24)** — already M46; re-confirmed at HEAD this shift. A Stuart Sierra
  `Component`/`System` pair grafted onto Hilt: `System` (:15) is never constructed, so the only
  orchestration (`components.reversed().forEach { it.stop() }`, :22) never runs. Hilt already owns
  singleton scope; the extra layer adds a mutable field and a *temporal* contract
  (`start()` before any `get()`) without adding capability.
- **`system/DatabaseSystem.kt` (31) / `system/NetworkSystem.kt` (26)** — the temporal contract is
  encoded as a runtime exception: `get() = _db ?: throw IllegalStateException("…not started")`
  (:16) and the same shape at `NetworkSystem.kt:12`. A `@Provides fun db(@ApplicationContext c: Context): AppDatabase =
  Room.databaseBuilder(…).build()` makes the failure mode unrepresentable — no `start()`, no
  ordering, no throw. This is the simplest change in the repo that deletes a whole class of bug.
- **`AlakeyApplication.kt` (32) + `MainActivity.kt` (45)** — two owners of one process-scope
  lifecycle (`:24-25` and `:28-29`). Idempotent today via the `if (_db != null) return` guards, so
  **no defect is claimed**; the cost is that the Activity's two `@Inject` fields (:19-20) exist
  solely to make two no-op calls, and it makes the Activity a plausible place to later wire
  `stop()` — which would hand a resumed UI a closed Room DB. Already M46-SHARPEN; no new ID.
- **`ui/PlaybackClient.kt` reconnect ladder** — bounded retry is the right instinct; a bound with no
  re-arm is a policy that gives up and then cannot be asked to try again (M64).
- **`service/Services.kt` (67)** — right size, right shape, one unreachable guard (L63).
- **LOC** — every file in this area is small (24–83). Repo-wide max is still `AlakeyUI.kt` 444 and
  `PlaybackClient.kt` 432: **0 files over the 500 hard ceiling** (`find app wear tile-contract -name "*.kt"
  -not -path "*/build/*" | xargs wc -l | sort -rn` → total 5 215, max 444).
