## Rich Hickey pass

- **ui/PlaybackClient.kt (432 LOC)** — over the 250 soft target, under the 500 hard ceiling. Complects four concerns in one class: media3 controller lifecycle + reconnect backoff, the event reducer, the sleep timer (three modes across three state fields), and prefs persistence. The reducer (`PlaybackEvent` → `reduce` → `processEvent`) is the good part: plain data in, plain data out, trivially testable — and nothing else in the file keeps that discipline. The reconciler is half-adopted (L21). Simplest fix that survives scrutiny: extract the sleep timer to its own class (it touches nothing but the `_sleepTimer*` flows and `pause()`), then either reconcile `mediaItem` or delete the field.
- **data/FeedRepository.kt (102)** — clean shape, one complection: `fetchValidFeed` composes direct-then-proxy with `looksLikeFeed` as the validity oracle. A `startsWith("<")` + "not an html doctype" sniff is a guess about content type standing in for actually parsing the thing; `RssParser.parse` already fails on garbage and is the real oracle. Two oracles answering one question.
- **data/DownloadRepository.kt (103)** — right size, wrong identity model: the download's identity is the URL, its filename is the podcast id (M20). Plain-data fix: name the file from the URL hash, or persist `{url, length, etag}` beside the partial and refuse to resume on mismatch.
- **system/NetworkSystem.kt (26) / data/NetworkCall.kt (33)** — both small and single-purpose. NetworkSystem's problem is the `Component` start/stop contract itself: it models a mutable lifecycle over something that should just be a provided constant (M22). NetworkCall is a fine retry helper missing one predicate, `retryable: (Throwable) -> Boolean`.
