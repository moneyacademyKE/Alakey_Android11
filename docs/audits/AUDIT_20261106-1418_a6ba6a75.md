## Rich Hickey pass

- **`ARCHITECTURE.md`** — the layering prose is simple and the mermaid diagram is the right shape, but it describes the app as it existed before `c9fdac7` added the wear module and before the repository split. A simple description of the wrong system is worse than a complex description of the right one: simplicity here reads as authority.
- **`COMPONENTS.md`** — a utility/complexity matrix is exactly the Hickey-correct artifact (data over prose, comparable at a glance). The data is stale. It rates a 73-line facade "🔴 High complexity" and issues strategic direction ("Freeze UniversalRepository", "consider composite repositories") for a decomposition that is already complete. Good format + wrong data is the most persuasive kind of misleading doc.
- **`UniversalRepository` (the code, not the doc)** — this is the correct move and the docs haven't caught up to the win: six injected collaborators, every method a one-line forward, no logic in the hub. That is composition, not a God Object. The incidental complexity was removed; only the description of it remains.
- **`TESTING.md`** — complects three unrelated toolchains (JaCoCo + Appium + MCP/`pip`) into one guide, none of which the repo wires up. The simplest true version is four lines: `./gradlew testDebugUnitTest`, plus `:tile-contract:test` (H7), plus the jacoco HTML path that already works. Everything else in the file is aspiration presented as instruction.
- **`.agent/workflows/release.md`** — `git add .` is the anti-composition move: it makes every release a function of whatever happens to be in the working tree. With 666 tracked build artifacts (M28) that guarantees noise, and it removes the one place a human would otherwise look at what is being shipped.
- **`WORKFLOWS.md` + `README.md` REPL sections** — documenting an interface from memory rather than from the dispatcher. The real `when` block at `ReplReceiver.kt:37-52` is 11 lines and would have been the single source of truth; instead the doc invented four commands and missed seven. Same disease as M32 and L36: the description was never re-derived from the code.
- **Gap Analysis** — omitted deliberately. Step 4 requires the table when a change spans 3+ files, adds a dependency, or alters an API boundary. This shift is a read-only docs audit and changes no code, so there is no feature-set diff to weigh. The remediation that follows from it (a docs pass) is 13 independent single-file edits, not an architectural decision.
