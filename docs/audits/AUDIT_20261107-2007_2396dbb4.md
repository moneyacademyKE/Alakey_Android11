## Rich Hickey pass

- `TileContract.kt` (50 LOC): **exemplary, verdict unchanged.** One module owns the wire format; pure data plus two pure functions; no Android, no GMS, no dependency beyond the JDK. `decode` never throws. The complection it correctly refuses is the obvious one — a `Parcelable`/protobuf/JSON schema that would drag Android types into a module both an app and a watch consume. String plus unit separator is the simplest thing that survives that boundary, and the exact 8-field count check makes every malformed input fail closed. Only the privacy of `FRAME_VERSION` costs anything (L76).
- `TileContractTest.kt` (60 LOC): **good coverage, brittle construction.** Six tests pin round-trip, empty metadata, frame uniqueness via timestamp, truncation, unknown version, and corrupt numbers/booleans — that is the right list. `:31-35` ("timestamp makes frames unique so the data layer never dedupes a push") pins a *behavioural contract with the Wear Data Layer*, not just a codec, which makes it the sharpest test in the repo. The brittleness is inherited, not authored: it must reconstruct the wire format by hand because the constants are private (L76).
- `tile-contract/build.gradle.kts` (16 LOC): **clean, one redundant declaration.** `:2 id("org.jetbrains.kotlin.jvm")` yields task `test`, not `testDebugUnitTest` — that single line is the whole of H7. `:5-8 java { sourceCompatibility/targetCompatibility = 17 }` and `:11 kotlinOptions.jvmTarget = "17"` state the same level twice through two mechanisms; harmless, and L32 already owns the tree-wide absence of a JVM toolchain, so this is cross-referenced rather than filed.
- Consumers: `TileFormat.kt` stays the shape M40 asks for in `Migrations.kt` — pure projection, clock injected (`isStale(np, nowMs = …)`), Android shell thin; its only flaw is the default clock, which is L74 (filed at 19:14, not re-filed). `NowPlayingTileService.kt:86` renders `mmss(positionMs) / mmss(durationMs)` — there is no division anywhere in the wear module, so `durationMs = 0` (an episode of unknown duration, which `decode` accepts) degrades to a displayed `0:00` rather than a NaN or a crash. Checked specifically; not a finding.
