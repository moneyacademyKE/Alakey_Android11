## Rich Hickey pass

- **`PlayerComponents.kt` (368 LOC)** — shape is right: `PlayerSpec` is plain immutable data, the composables are dumb renderers over it, and the two pure functions (`formatMs`, `shouldDismissPlayer`) are the only logic worth testing and *are* tested (`AppReducerTest.kt:70-77`). The complect is **time**: M17 wires a permanent clock into a button whose animation is only meaningful while buffering, and M18 lets an external async event (buffering) mutate whether the component can clean up its own local state. Both are the same mistake — state whose lifetime is not owned by the thing that created it. Under the 500 ceiling, over the 250 soft target.
- **`AlakeyUI.kt` (444 LOC)** — the largest file in the repo and it is a grab-bag: root scaffold, headset broadcast receiver, shake sensor, spec derivation, library list, episode list, swipe-to-dismiss, empty state, sleep sheet, add dialog, search row, and a `SensorEventListener` class. Nine concerns in one file. Two concrete costs of that: L16 (a spec-derivation helper with a defaulted parameter that one of three callers forgets) and L17 (the same fact arriving twice). Splitting `AddPodcastDialog` + `SearchResultRow` (~55 LOC) and `MotionDetector` (~25 LOC) out would leave it near 360 and remove both seams. No new abstraction needed — just moving the existing seams to file boundaries.
- **`AppViewModel.kt` (392 LOC)** — `searchPodcasts` (:293-308) is genuinely good: job cancellation, a 300 ms debounce, and a generation counter guarding against out-of-order responses. The flaw is downstream — it stores only the success value, which is exactly what forces the UI to guess state from emptiness (M19). The repository already returns a `Result`; flattening it to a bare list at the ViewModel boundary throws away the failure the UI needs.
- **`AnimationPolicy.kt` (21 LOC)** — the right idea, and the reason M17 is a cheap fix: a pure `shouldAnimateAmbient(isResumed, animatorScale)` plus a `@Composable` reader that swallows the `Settings.Global` throw with a sane default. Small, composable, no incidental complexity. It just has one consumer (`GlassSystem.kt:36`) when it should have two. One nit: `rememberAmbientMotionEnabled()` hardcodes `isResumed = true` (:19), so the pure function's `isResumed` parameter is never exercised — dead flexibility until a lifecycle-aware caller exists.
- **`UISpecs.kt` (50 LOC)** — `PlayerSpec` / `PodcastRowSpec` as flat data records is exactly the composition this UI needs. The defaults (`sleepTimerTotalSeconds = 0`, `speed = 1.0f`) are what let L16 slip through: a default on a field that changes rendering is an invitation to omit it.
