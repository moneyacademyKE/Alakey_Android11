## 2. Critical

### C1. Every schema upgrade wipes all user data
`DatabaseSystem.kt:24` — `fallbackToDestructiveMigration()` on `alakey-db`, and `AppDatabase.kt:6` declares `version = 13, exportSchema = false`.

The DB holds subscriptions, playback progress, queue, facts, event logs. The app is 13 schema revisions in with **zero migration paths** — each bump silently drops the whole database. For a product whose pitch is *smart playback continuity*, the upgrade path is a factory reset.

**Fix:** set `exportSchema = true` (commit the schemas), write real `Migration` objects from now on, add `MigrationTestHelper` tests. Room also offers `fallbackToDestructiveMigrationOnDowngrade()` as the only acceptable destructive case.

## 3. High

### H1. "Releases" are debug APKs — the REPL ships to end users
`.github/workflows/android.yml` — build job runs `assembleDebug` only; the release job publishes that artifact. There is **no signing config anywhere in Gradle** (`keystore.properties` exists locally but is referenced by nothing), and no `assembleRelease` step. Consequences for every GitHub Release:

- `app-debug.apk` is debug-signed — not upgradeable over a differently-signed install.
- R8/minify is **never exercised** — the release code path is untested.
- `src/debug/AndroidManifest.xml:10` — the `ReplReceiver` (exported, see M1) is **in the published APK**, with `exec-sql` arbitrary-SQL capability.

If debug-distribution is deliberate (sideload-only), document it and gate the REPL behind a build flag; otherwise add a signed `assembleRelease` job using CI secrets.

### H2. Playback core is ~3 years behind
`gradle/libs.versions.toml`:

| Dependency | Pinned | Age at audit |
|---|---|---|
| `media3` | 1.2.0 | Dec 2023 — years of ExoPlayer/session fixes missed |
| `compose-bom` | 2024.02.00 | Feb 2024 |
| `kotlin` | 1.9.22 | pre-K2 |
| `hilt` | 2.50 | Jan 2024 |
| `retrofit` | 2.9.0 | 2022, and **unused in code** |

The playback-reliability churn in commits #59–#62 (controller rebuild, FGS promotion, disconnect handling) is exactly the class of bug that media3 point releases have been fixing upstream since. Meanwhile `core-ktx 1.17.0` and `lifecycle 2.10.0` are current — the catalog is two eras stitched together.

**Fix order:** media3 → Compose BOM → Kotlin 2.x (removes the hand-pinned `kotlinCompilerExtensionVersion`) → drop `retrofit` and `okhttp-logging-interceptor` (both zero usages).

## 4. Medium

- **M1. ReplReceiver exported, unguarded** — `app/src/debug/AndroidManifest.xml:10` + `ReplReceiver.kt:47`. Any app on the device can broadcast `exec-sql <arbitrary SQL>`, `assert-fact`, or playback commands to a debug build. Debug-only is good; exported is not. **Fix:** `exported="false"` — `adb shell am broadcast -n com.example.alakey/.debug.ReplReceiver` still works (shell uid is exempt from the exported check), so nothing is lost.
- **M2. Third-party CORS proxy fallback leaks feed URLs** — `FeedRepository.kt:84` `https://api.allorigins.win/get?url=$url`. Feed subscriptions go to a random third party whenever direct fetch fails; `$url` is also interpolated unencoded (URL injection / breakage on `&`). **Fix:** drop the proxy, or encode with `HttpUrl.Builder` and surface the privacy tradeoff in UI.
- **M3. Media session accepts every controller** — `Services.kt:28-33`, empty `MediaLibrarySession.Callback` and `onGetSession` returns the session unconditionally. Any app can connect, control playback, and browse the library tree. **Fix:** validate `ControllerInfo` package/TrustLevel in `onGetSession` (reject unknown controllers unless `isTrusted`).
- **M4. The three biggest files have zero tests** — `AlakeyUI.kt` (444), `PlaybackClient.kt` (432), `AppViewModel.kt` (392); total test LOC is 418 vs 5,251 source. Also `app/build.gradle.kts` sets `unitTests.isReturnDefaultValues = true`, which masks framework misbehavior with default values. Known bug hiding in the gap: `PlaybackClient.resume()` reads `controller?.currentPosition ?: 0L` — if the controller is mid-rebuild after a disconnect, resume seeks to ~0 and loses position.
- **M5. `FOREGROUND_SERVICE_DATA_SYNC` declared, no consumer** — `AndroidManifest.xml:8`. The `AudioDownloadWorker` is gone (confirmed: zero references); downloads run inline in `DownloadRepository`. Unused FGS permissions are Play-review flags. **Fix:** remove it.
- **M6. Sync worker has no network constraint** — `FeedSyncWorker.kt:29` enqueues periodic work without `Constraints(NetworkType.CONNECTED)`; offline windows burn retries on guaranteed failure.
- **M7. iTunes search builds the URL by string concat** — `FeedRepository.kt:28` `"?term=$query&..."`. A query containing `&`/`#` truncates or mangles the search. **Fix:** `HttpUrl.Builder().addQueryParameter`.

## 5. Low

- **Docs drift:** `ARCHITECTURE.md` still documents `AudioDownloadWorker` (removed) and the Worker→Repo→OkHttp path no longer matches the fact-store download flow. `PodcastEntity` actually models *episodes* (see `UniversalRepository.getPodcastsByTitle` → `dao.getEpisodesByTitle`) — the name lies.
- **Committed cruft:** `build_log.txt` (a build log, in git), `optimize_env.ps1`, `test_dev_mode.ps1` (Windows scripts in a macOS-only workflow), 0-byte dead `service/DownloadService.kt`, unregistered duplicate `repl/ReplReceiver.kt` in the main source set (the live one is debug-only), template `ExampleUnitTest`/`ExampleInstrumentedTest`, `Gson()` instantiated per conversion in `AppDatabase.kt` Converters.
- **Proguard file is the untouched stock template** with R8 enabled — no `-keepattributes SourceFile,LineNumberTable`, no mapping upload in CI. Release crash traces will be unobfuscatable.
- **`syncAll` swallows per-feed failures** — `FeedRepository.kt:52` `printStackTrace()` instead of an event-log entry; the observability system exists and isn't used here.
- **Backup rules are placeholder templates** — `allowBackup=true` with stock `backup_rules.xml`/`data_extraction_rules.xml` (all comments). The library DB lands in cloud backup by default. Low sensitivity, but say so deliberately.
- **Plugin versions declared twice** — root `build.gradle.kts` uses literals while the catalog carries the same versions; drift risk.

## 7. What earns credit

- Secrets hygiene is flawless: keystores, `keystore.properties`, `local.properties` all gitignored and untracked; zero secret material in 805 tracked files.
- `network_security_config.xml`: cleartext forbidden globally, system trust anchors only.
- `DownloadRepository` is genuinely well-engineered: HTTP Range resume with correct 416/206/200 handling, streamed 64KB copy, SHA-256 filenames (path-traversal-proof), progress callbacks.
- `PlaybackClient` reconciler (desired-state vs controller) with bounded exponential reconnect (#61) is the right architecture; the event-reducer split keeps 432 LOC readable.
- LOC discipline: all 76 files under the 500 hard ceiling (max 444); zero TODO/FIXME markers; zero `!!` force-unwraps in main sources.
- Honest commit history, PR traceability, and a release pipeline that already globs artifacts per release (#55).

## 8. Fix order (cheapest informative step first)

1. **C1 migrations** — the only finding that destroys user data on routine upgrades.
2. **H1 release path** — decide: signed `assembleRelease` in CI, or documented debug-sideload policy. Either way, stop silently shipping the REPL.
3. **M1 + M5** — one-line manifest changes (`exported=false`, drop `DATA_SYNC` permission).
4. **H2 media3 bump** — highest-probability fix for residual playback weirdness; watch the #61/#62 behaviors as regression targets.
5. **M2/M7 URL handling** — encode queries, decide the proxy's fate.
6. **M4 tests** — port the PlaybackClient reducer to pure testable units; kill `isReturnDefaultValues` eventually.
7. Docs + cruft sweep (L-group) — one housekeeping PR.
