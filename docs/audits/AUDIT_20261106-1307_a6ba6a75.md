## Rich Hickey pass

- **`settings.gradle.kts` (25)** — the cleanest file in the area. `RepositoriesMode.FAIL_ON_PROJECT_REPOS` (`:15`) means modules cannot invent repositories; that is a real constraint doing real work. Change nothing.
- **`build.gradle.kts` (7)** — five plugin-version literals that duplicate the catalog. Simplest correct form is `alias(libs.plugins.x) apply false` ×5 with the literals deleted: one source of truth, no new abstraction, and it fixes L6/M29 in the same edit.
- **`gradle.properties` (23)** — 18 of 23 lines are Android Studio boilerplate comments; of the 5 live settings, all are defaults except `org.gradle.jvmargs`. `org.gradle.caching` is absent (`grep` = 0 hits), so CI recompiles from scratch every run (1m52s) despite `cache: gradle` caching `~/.gradle`. `:24` still carries a commented **Windows** `org.gradle.java.home` path in a macOS-developed repo. Delete the prose, add caching, add the toolchain (L32).
- **`gradle/libs.versions.toml` (77)** — 30 version keys, 41 libraries, 2 plugins; 4 libraries and both plugins are referenced by nothing. A catalog that is not the source of truth is worse than no catalog: it is a plausible-looking place to make a change that does nothing (M29).
- **`gradle-wrapper.properties` (8)** — gradle-8.13-bin, `validateDistributionUrl=true`, no `distributionSha256Sum`. Wrapper jar *is* tracked (`git ls-files gradle/wrapper` → jar + properties), so a clean clone builds. Checksum pinning is the one missing hardening line — recorded as a note, not a finding: the distribution is HTTPS-only and this is hardening, not a defect.
- **`app/build.gradle.kts` (123)** — under the 500 ceiling but complecting four jobs: variant config, dependency list, test options, and a 24-line hand-rolled jacoco task (`:100-123`) with hardcoded paths (`tmp/kotlin-classes/debug`, `outputs/unit_test_code_coverage/debugUnitTest/testDebugUnitTest.exec`) that break on any AGP layout change, in a module pair where only one of three modules has it. That block belongs in a shared `gradle/coverage.gradle.kts` or nowhere until CI runs it (L30).
- **`wear/build.gradle.kts` (40)** — `:24-30` duplicates `app:36-42` verbatim (compileOptions + kotlinOptions). At two modules a convention plugin is arguably the *more* complex answer, so I'd keep that duplication; what I would not keep is the unshrunk Guava riding on the `isMinifyEnabled = false` decision (M31).
- **`tile-contract/build.gradle.kts` (16)** — correct and minimal, plain data + a JVM compile. Its only defect is downstream and already filed: the `kotlin.jvm` plugin makes the test task `test`, which is why CI's `testDebugUnitTest` never runs it (H7).
- **`app/proguard-rules.pro` (20)** — stock template, zero project rules, keeps commented out. This is a file that exists to be edited and never was (L3).
- **`.gitignore` (22)** — `/build` root-anchored at `:3` is M28's entire root cause, one character (`/`) from correct. `*.keystore` appears twice (`:7` and `:22`) — harmless, but it says the file grew by accretion rather than by decision.
- **`.github/workflows/android.yml` (68)** — three Gradle invocations in one job, no concurrency guard, no timeout, no lint, no coverage, no tile-contract test, and a release job that ships debug bits. Every one of those is a 1-3 line change. This file is where the repo's robustness is cheapest to buy.
