## Rich Hickey pass

- `app/src/test/**` (29 tests, 6 files, 337 LOC): the suite tests what is *easy*, not what is
  *load-bearing*. Every test targets a pure static (`RssParser.parse`, `ChapterParser.parse/timeToMs`,
  `FeedRepository.looksLikeFeed`, `InformationModel.hydrate`, `AppReducer.reduce`, `TileContract.encode/decode`).
  That is correct instinct — pure data in, data out — but it stops exactly where the state begins, so
  the modules that hold every open high finding (PlaybackClient 432, AppViewModel 392, AlakeyUI 444)
  are reachable only as a namespace: no test constructs an `AppViewModel`. Simplicity verdict: good.
  Composition verdict: the code under test was not written to be composed with a test double, so the
  suite's shape mirrors the code's coupling rather than exposing it.
- `AppReducerTest.kt` (79 LOC, 2 classes): reducer tested as the pure function it is — the best-shaped
  test in the repo, and the proof that the reducer/state split pays for itself. The second class
  (`UxPolicyTest`) belongs in its own file: one file, one idea.
- `tile-contract/src/test` (60 LOC / 50 LOC under test, 6 tests): round-trip + truncation + bad-version +
  corrupt-number. This is what a contract test looks like — and H7 means CI never runs it. The repo's
  best tests are its least-enforced ones; that is a build-graph bug, not a testing bug.
- `wear/src`: no test sourceset at all (`find wear/src -maxdepth 2 -type d` → `main/`, `main/res`,
  `main/java`). 137 LOC of `NowPlayingTileService` + 73 `WearBridge` + 44 `WearCommandListenerService`
  with zero JVM pins (M11 residual; PR #76 adds `TileFormatTest`).
- Gap Analysis (test-infrastructure change spans 3+ files and alters the CI boundary):

  | Option | Adds | Cost | Catches |
  |---|---|---|---|
  | A. `./gradlew test tile-contract:test` → change workflow line 29 to `./gradlew testDebugUnitTest :tile-contract:test` | 1 line in `android.yml` | ~1s CI | H7 immediately — 6 tests start gating |
  | B. Add `connectedAndroidTest` emulator job | 1 workflow job (~10 min CI) | emulator flake risk | M25 — but only 1 test exists to run |
  | C. Delete `isReturnDefaultValues`, add mockito/coroutines-test usage | touches app tests | real work | L27/M27 — makes the next PlaybackClient bug pinnable |
  | D. JaCoCo threshold gate | 1 workflow step | blocks merges on unrelated PRs | L30 — but a threshold on an 80%-untested repo is a wall, not a ramp |

  Recommendation: **A now** (one line, unblocks 6 real tests), **then C targeted at PlaybackClient**
  (H5/H6 are the highest-severity open findings and both are pure state-machine bugs reachable with
  `runTest` + a fake controller). B and D are ceremony until there are tests worth running and a
  coverage ramp worth enforcing. Reject the tempting "add a coverage gate first" ordering — it
  complects a policy decision to a suite that cannot yet satisfy it.
