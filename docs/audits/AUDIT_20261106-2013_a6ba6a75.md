### M43 — detail

PR #76 replaced `items.map { hydrate(it) }` (one `getLatestFacts` JOIN per episode) with a single `factDao.getAllFacts().groupBy { it.entityId }`. That genuinely kills the N+1 — but the query it swapped in has no predicate at all:

```
FactDao.kt:25   @Query("SELECT * FROM facts")
FactDao.kt:26   suspend fun getAllFacts(): List<FactEntity>
```

So cost is now `O(entire fact history)` in JVM heap on every call, instead of `O(facts for these ids)` across N queries. `hydrateAll` is called from five production sites, including one **per media-item transition**:

```
data/PlaybackStateRepository.kt:33, :52, :60, :65
data/DownloadRepository.kt:33
data/UniversalRepository.kt:36
```

**Growth rate, derived from the code, not guessed.** The save loop is `PROGRESS_SAVE_INTERVAL_MS = 5_000L` (`AppViewModel.kt:389`, gate at `:150`). Each save runs `:154 updateProgress` → `PlaybackStateRepository.kt:19 assert(ATTR_PROGRESS)` **and** `:20 updateLastPlayed` → `:24 assert(ATTR_LAST_PLAYED)`, then `:155 updateLastPlayed` again → a third assert (that is M44). Three rows per save, one save per 5 s of playback:

- 36 rows/minute → **2,160 rows/hour of listening**, every one of them superseded within 5 seconds of being written.

The only thing that ever removes them is `FactDao.compact()` (`:35-41`, keeps `MAX(tx)` per `(entityId, attribute)`), reachable solely from `AppViewModel.kt:118`:

```
init { viewModelScope.launch { repo.compactFacts() } }   // "once per app open (#57)"
```

Nothing compacts during a session. A long listening session therefore accumulates thousands of dead rows, and `hydrateAll` materialises all of them into a `List<FactEntity>` — then does `groupBy { attribute }.values.mapNotNull { maxByOrNull(tx) }` per item (`InformationModel.kt:31`), i.e. the max-resolution the DB could have done is redone in Kotlin over the full history.

**This is exactly M12's shape** — unbounded row growth fixed with a retention sweep — applied to the one table that got no sweep. M12's fix runs *per sync*; the facts equivalent runs *per app open*, against a table that grows 18× faster than `event_log` does.

Honest calibration: no OOM was observed or reproduced, and a process restart resets the window, so this is an accumulation hazard rather than a demonstrated crash (conf: h on the mechanism and the arithmetic, m on real-world impact).

**Cheapest fix, and it is a deletion, not an addition.** `getLatestFacts` (`FactDao.kt:43-52`) already expresses "latest tx per (entityId, attribute)" as SQL — it is only scoped to one entity by the `WHERE entityId = :entityId` at `:48`. Drop that predicate and `GROUP BY entityId, attribute` and `hydrateAll` becomes one query that returns *only live facts*, with the DB doing the grouping. That is strictly less code than today, keeps M13's N+1 fix, and makes memory `O(live facts)` instead of `O(history)`. Belt-and-braces alternative: `compact()` after the purge in `FeedRepository.syncAll` (`:73`), where M12's sweep already runs.

## Rich Hickey pass

- **`FactStore.hydrateAll`** — the fix is directionally right (one query beats N) but it complects *hydration* with *whole-table materialisation*, and then re-derives in memory the max-per-attribute the SQL layer already knows how to express. The data was already there; the query just stopped filtering it. M43's fix removes a predicate rather than adding machinery.
- **`EventLog.escapeLike`** — this is the good shape, and worth naming as the counter-example in the same PR. One pure function, no IO, injected at the single place the untrusted string crosses into SQL (`ObservabilityRepository.kt:16`), pinned by four JVM tests (`EventLogEscapeTest.kt:12,:17,:23,:28`). Escape ordering is also correct: backslash is doubled *first* (`EventLog.kt:51`), so the later `%`/`_` passes cannot re-escape their own output.
- **`AppDatabase.Converters`** — shared Gson instance replaces per-call construction; guards are explicit and tested. One shape note recorded as VERIFIED-GOOD rather than filed: `runCatching { … }.getOrDefault(emptyList())` only substitutes on a *thrown* exception, never on a null return, so the non-null `List<Chapter>` return type is protected by the `isBlank()` / `== "null"` guards at `:41` and not by the `runCatching`. Probed with Gson 2.10.1 from the local Gradle cache (JDK 21, single-file run): `"null"` → returns null, no throw; `""` → null, no throw; `"   "` → null, no throw; `"{not json"` → `JsonSyntaxException`; `"[]"` → `[]`. Both null-returning shapes are guarded, so there is **no live bug** — but the safety lives in the guard, not in the fallback, and a future input shape that parses to null would slip past a line that reads as if it were total.
- **`AppDatabase` / `RoomSchema`** — `version = RoomSchema.VERSION` with `exportSchema = true` and both `13.json`/`14.json` committed is the right move: the migration source of truth is now data in the repo instead of a magic literal. Small blemish, not filed: `RoomSchema.VERSION` and `AppDatabase.SCHEMA_VERSION` state the same constant twice.
