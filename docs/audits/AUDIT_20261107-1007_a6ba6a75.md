### M65 — the history buffer
`updateState` (:252) is the single state-transition funnel: `_uiState.update { current -> val next = transform(current); if (next != current) { _history.add(next); if (_history.size > 50) _history.removeAt(0) } ; next }` (:253-260). Two defects in three lines:
1. **Nothing reads it.** `history` (:110) has no consumer in any source set; the only code shaped for it is `DebugOverlay(historySize, onTimeTravel, logs)` (:19-20), which is never called. `UiState` carries six list fields (`navigationStack`, `podcasts`, `optimisticPodcasts`, `queue`, `inbox`, `chapters`), so up to 50 generations of those lists stay pinned for the process lifetime, plus one `mutableStateListOf` write per transition — a snapshot-system write on the main thread, per playback tick, for nobody.
2. **The side effect sits inside `MutableStateFlow.update`'s transform** (:253), which the flow may invoke more than once under contention; a non-idempotent write there can append the same state twice. Harmless today only because the buffer has no reader — which is exactly the kind of trap that fires when someone "finishes" time-travel.
Fix: delete :109-110 and :255-257 (the `next != current` guard exists only for the buffer; `update` already tolerates an equal value), or move the buffer outside the CAS lambda and give it a reader. Retained bytes NOT measured — no build this shift (M28). Conf h — status: open.
