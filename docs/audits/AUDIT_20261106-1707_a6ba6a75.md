## Verified GOOD on PR #76 (recorded so no future shift re-litigates it)

- **C1 is genuinely fixed.** `DatabaseSystem.kt:55-56` = `.addMigrations(MIGRATION_13_14)` +
  `.fallbackToDestructiveMigrationOnDowngrade()` — the *unqualified* `fallbackToDestructiveMigration()`
  that HEAD still carries (`C1-BROADER`) is gone on the PR. The wipe decision is now a pure function
  (`legacyDecision` `:30`) with `MIGRATION_FLOOR = 13` (`:98`), and the below-floor path backs up to
  `alakey-db.pre-v14.bak` (`:82`) before deleting the db + `-wal`/`-shm`/`-journal` (`:86-89`).
  An unreadable version yields `PassThrough`, i.e. never wipe on a read failure (`:30-35`, pinned by
  `LegacyDecisionTest`).
- **M14's rewrite is NOT a silent no-op** (the failure mode this shift went looking for). The migration's
  proof gate `Migrations.kt:34` `(feedUrl + audioUrl).hashCode().toString() != id` matches v13's actual id
  derivation **exactly**: `fork/master:app/src/main/java/com/example/alakey/data/RssParser.kt:57`
  `id = if (guid.isNotEmpty()) "$feedUrl/$guid" else (feedUrl + audioUrl).hashCode().toString()`.
- **The rewrite is idempotent and cannot collide.** `EpisodeIds.kt:30-31` caps legacy detection at
  `id.length <= 11`, while `derive` (`:18-22`) always emits 16 hex chars; guid ids are `"$feedUrl/$guid"`
  and always contain `/`. Early return on an empty map (`Migrations.kt:38`) and the
  `executeUpdateDelete() > 0` guard (`:45`) keep the facts update tied to a real podcast update.
- **No entity change rode along with the version bump.** `app/schemas/.../13.json` vs `14.json`: both
  218 lines, identical on every `tableName`/`columnName`/`affinity`/`notNull`/`primaryKeyPosition`, the
  only diff being `"version": 13` → `14` (line 4 of each). Room's runtime schema validation therefore has
  nothing new to reject on merge.
- **`"%016x"` is locale-safe** — checked, not assumed. JDK 21 single-file probe with
  `Locale.setDefault` over `en_US`, `ar_SA`, `th_TH`, `de_DE`: `-1L` → `ffffffffffffffff`,
  `0x0123456789abcdefL` → `0123456789abcdef`, `len=16`, `asciiOnly=true` in all four; the exact
  `EpisodeIds.derive` byte-fold gives `77f686eee32e593e` for `"feed|audio"` under both `ar-SA` and `en-US`.
  The KDoc's "16 lowercase hex chars, unsigned" claim holds, including for a negative folded long.

## Rich Hickey pass

- `data/Migrations.kt` (53 LOC): **good shape, one missing datum.** The migration already computes the
  authoritative `oldId -> newId` map (`:29-37`) and then throws it away (`:51` logs only the count).
  M39 exists purely because that map never leaves the transaction — the filesystem needs it and cannot
  see it. Cheapest correct fix: persist the pairs into `event_log` (`EventLog.kt:13` payload is
  "JSON or simple ID") inside the migration, then let a one-shot post-open step in `DatabaseSystem`
  (which *has* `context`) rename `<sha256(oldId)>.mp3` → `<sha256(newId)>.mp3` and delete the markers.
  ~20 lines, no schema change, no new dependency. Durable alternative: stop deriving the file name from a
  mutable id at all — resolve from the stored `episode.audioPath` fact (data, not derivation) and add an
  orphan sweep for `filesDir/*.mp3` names no fact references.
- `system/DatabaseSystem.kt` (100 LOC): **the right decomposition.** Extracting `legacyDecision` as a pure
  sealed-interface function is exactly the move that made C1's floor semantics testable, and it is the
  pattern M40's fix should copy.
- `data/EpisodeIds.kt` (32 LOC): **simple and honest.** One digest, one fold, one predicate; the KDoc
  states the collision bound (~77k at 32 bits vs ~5e9 at 64) rather than hand-waving.
- `data/DownloadRepository.kt` (103 LOC): **complects identity with storage.** The file name is recomputed
  from the id at every call (`:45`) while the authoritative path is *also* stored as a fact (`:61`) — two
  sources of truth for one thing, and they diverge the moment the id changes. That is M39's root cause and
  it predates #76.
