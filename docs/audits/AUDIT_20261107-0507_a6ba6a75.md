## Rich Hickey pass

- **theme/Theme.kt (63 LOC)** — wrong shape, and M57 is the proof. It is a *configurable* abstraction (two parameters, four branches) with two callers that both pin both parameters identically. The configuration is the complexity; nobody consumes it. Simplest shape that survives scrutiny: delete `AlakeyTheme`'s parameters, the dynamic-color branch and `LightColorScheme`, leaving a 10-line `AlakeyTheme(content)` that always supplies `DarkColorScheme` — and then actually *use* the scheme, replacing the 10 hardcoded `0xFF00F0FF` sites with `MaterialTheme.colorScheme.primary` so one cyan exists. That is data over duplication, and it collapses 37 literals toward 5.
- **res/values/themes.xml (4) + colors.xml (2)** — colors.xml is an empty file that should not exist; themes.xml is one style with the wrong parent for an all-black app (M58). Two files, one live declaration, one live defect. Compose them into one correct theme rather than keeping a decorative empty resource.
- **mipmap-anydpi + 10 webp buckets (M59)** — the complect is *two* icon systems shipped at once (adaptive XML and legacy rasters) where minSdk 30 needs only the adaptive one, and the adaptive one is fed a photograph where it needs alpha. Delete the rasters, supply a real alpha-masked foreground and a flat monochrome glyph: less data, correct rendering.
- **backup/data-extraction templates (L57)** — the repo ships a *policy placeholder* where a *policy* belongs. An empty `<cloud-backup>` is not "no decision", it is "back up everything including 100 MB of MP3s". Naming the decision explicitly (exclude downloaded audio, include the DB) is the whole fix.
- **No Gap Analysis table**: this shift changes no code, adds no dependency and crosses no API boundary (read-only audit) — the 3+ file / new-dependency trigger does not apply.
