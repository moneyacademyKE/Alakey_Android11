### M49 — honest calibration (do not overstate)
Mitigations **verified present**, which narrow this considerably:
- `network_security_config.xml:3` `cleartextTrafficPermitted="false"` in `base-config`, with **no**
  `domain-config` override → a plain `http://192.168.1.1/` chapters URL is blocked by the platform.
- Trust anchors are `certificates src="system"` only → an internal host with a self-signed cert fails
  the TLS handshake.
- OkHttp's `HttpUrl` accepts only http/https, so `file://` / `content://` throw
  `IllegalArgumentException` inside `runCatching` (FeedRepository.kt:79) and are swallowed at :84 —
  no local-file read.

Residual exposure, stated plainly: a hostile feed can still direct an outbound **https** GET from the
user's device to an attacker-chosen host (device IP + UA leaked), to internal/link-local hosts that
hold a system-trusted cert, and can use success/latency as a reachability oracle. Classified as a
**hardening gap, not a demonstrated exploit** (conf: m on mechanism, l on impact) — the same honesty
shape as L25.

Cheapest fix is one line at the parse edge, so a bad value never reaches the entity or the DB:
`HttpUrl.parse(raw)?.takeIf { it.scheme == "https" }?.toString()`. Validation belongs where the
untrusted data enters, not at the fetch. **Not applied** — no auto-fix approval.

### M46-SHARPEN — why the double start matters
Neither `_db` (DatabaseSystem.kt:42) nor `_client` (NetworkSystem.kt:11) is `@Volatile`, and both
`start()` bodies are check-then-act (`if (_client != null) return`, NetworkSystem.kt:14-15). On the
normal launch sequence — `Application.onCreate` then `MainActivity.onCreate`, both on the main thread —
the guard holds and this is benign; **no race is claimed for that path**. It is not safe under any
off-main-thread caller, and the failure mode is an orphaned `OkHttpClient`: a dispatcher
`ExecutorService` and `ConnectionPool` that nothing ever shuts down, because `stop()` (:22-25) only
nulls the reference (M22's residual, LATENT per M46). Cheapest shape is a **deletion** — remove
MainActivity.kt:28-29 and let `Application` own the component lifecycle — which is the same
"less code than today" answer M43 got.

## Rich Hickey pass
- **ChapterParser.kt (45 LOC)** — right shape, wrong contract. A pure object, no Android, JVM-testable,
  returns `List<Chapter>` and never throws. The regex is the complection: it encodes an *ordering*
  assumption about JSON, which the format does not make. Plain data would be a small hand-rolled
  brace-matching scan or `org.json`; the comment at :5 rejects `org.json` to keep it JVM-pure, which
  is a real trade — but the purity was bought with a correctness hole (M23).
- **RssParser.kt (102 LOC)** — good: pure on `(xml, feedUrl)`, immutable values out, no state.
  `directElements` (:89-99) walking `childNodes` by hand is exactly the simplicity the namespace
  unawareness costs — it is honest about what it does. The `catch (e: Exception)` at :29 is too wide.
- **FeedRepository.kt (116 LOC)** — the best-shaped file in this chain after #76: single-pass `subscribe`
  matching its own comment (:45-46), `use{}` on every Response (:39, :80, :98), the proxy gone, the
  purge inside the mutex (:73). One trap worth recording: `return@use emptyList()` at :81 is a **lambda**
  return, not a non-local return, so the Response still closes — it reads as a bug and is not one.
- **NetworkSystem.kt (26 LOC)** — 26 lines to hold one OkHttpClient. The abstraction earns nothing
  today (`client` throws if unstarted, `stop()` is unreachable per M46); the mutable nullable var is
  the whole problem surface. A `by lazy { OkHttpClient.Builder()... }` would delete `start()`, `stop()`,
  the guard, the nullability and both call sites — strictly less code, same behaviour.
