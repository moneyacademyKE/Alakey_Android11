## Rich Hickey pass

- **`service/Services.kt` (83 master / 94 PR #78):** the shell really is humble — no playback state, delegates to `AudioSystem` and media3. The complection is that ONE boolean is asked to answer three questions: "may this controller drive playback?", "may it read the library?" and "is this caller a platform bridge?". PR #78 answers the first by widening it and never asks the other two. The gate is already a pure function of `(package, version)` — data, not abstraction — so the fix is one more term in that function, not a new type.
- **`workers/FeedSyncWorker.kt` (40 master):** 6 lines of `doWork` that promise error handling and provide none (`catch (e: Exception) { Result.retry() }` at `:20-22`, `e` unused, no log) — M67/L13. **PR #78's rewrite is the right shape** (`:18-30`): outcome data out of the repository, retryability decided in the worker, cancellation rethrown as a lifecycle event rather than flattened into data, failure logged. Simple, and each part composes.
- **`system/AudioSystem.kt` (83):** re-reading prefs at every `STATE_READY` (`:40-48`) is the simple choice and the right one. The defects are invisibility (`runCatching` at `:57-62` and `:66`, zero logs — L14) and rebuilding the `LoudnessEnhancer` on every READY whether or not the toggle changed (`:52-53`).
- **`system/Lifecycle.kt` (24):** `class System(private val components: List<Component>)` at `:15` is instantiated **nowhere** — `grep -rn "= System(\|System(listOf\|: System" --include="*.kt" app/src wear/src` returns only `PlaybackStateRepository.kt:36`'s `System.currentTimeMillis()`. Three classes implement `Component` for a composite that is never composed. Already filed as M46; re-anchored, not re-filed.
- **The complection to name this shift:** this area keeps fixing the *mechanism a finding names* instead of the failure mode behind it — M9→M41, L8→M42, M10→H10, and now H4→M75. In each case a boolean stood where a policy belonged, and the fix swapped the boolean.
