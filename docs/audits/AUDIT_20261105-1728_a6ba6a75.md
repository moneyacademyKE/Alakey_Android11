## Rich Hickey pass

- **`TileContract.kt` (50)** — the best-designed file in the set. Pure data + pure functions, no Android or GMS imports, JVM-testable from both ends, and it actually has a test. This is the shape the rest of the module should imitate. One blemish: the codec trusts its own comment over the data it handles (L8).
- **`TileStateStore.kt` (33)** — complects three jobs (in-memory cache, prefs persistence, empty-state sentinel) and picks an observable abstraction with no observers (L9). Simplicity says `@Volatile var` + prefs; the sentinel says a missing `NowPlaying?` type.
- **`NowPlayingTileService.kt` (137)** — the layout code is genuinely clean: small `text`/`spacer`/`glyph` helpers, no nesting abuse, constants in a companion. The problems are semantic, not structural: it points its only interaction at an unreachable target (H3) and treats stored data as present truth with no notion of age (M9).
- **`NowPlayingDataListenerService.kt` (32)** — structurally the strongest of the four. `try/finally { dataEvents.release() }` is correct (iterating a `FrozenList` after release crashes), composition is right (depends only on `TileContract` + `TileStateStore`), and it does call `requestUpdate` — the classic Wear tiles omission is absent here. Only gap: silence on failure (L8).
- **`ToggleActivity.kt` (31)** — correct trampoline shape: `applicationContext` not activity context, `isNearby` filter so it never messages a cloud node, `finish()` before the first frame. The defect is not in the file, it is in the manifest line that makes the file unreachable. Better still, the file is incidental complexity that option A deletes outright.
- **`WearBridge.kt` (73)** — right idea (the phone stays the single truth, the watch only renders), wrong mechanism: polling is complected with presence (M10), and "best-effort" is asserted rather than observed (M9).
- **`WearCommandListenerService.kt` (44)** — the sharpest mismatch between comment and code in the module (M8). Credit where due: it posts the listener executor to the main looper rather than using `directExecutor()`, which correctly satisfies media3's `verifyApplicationThread()` — someone knew that rule.

LOC: largest audited file is `NowPlayingTileService.kt` at 137; the whole wear surface is 233 LOC. Nothing approaches the 500 ceiling. Repo-wide max remains `AlakeyUI.kt` at 444.
